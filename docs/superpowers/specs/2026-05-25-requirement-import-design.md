# 需求导入 Excel 功能设计

**日期**: 2026-05-25
**状态**: 待审核

---

## 1. 功能概述

在需求管理页面新增「导入」功能，用户可：
- 点击「下载模板」获取Excel模板文件
- 填写模板中的需求信息
- 上传填写后的Excel实现批量导入（新增或更新需求）

---

## 2. 权限控制

新增权限项 `requirement_import`：
- 白名单控制导入按钮和下载模板按钮的显示
- 后端接口检查权限，未授权返回 403
- 默认配置：`admin`、`管理员`角色可见（参考 `requirement_export` 模式）

**数据库迁移**: 新增权限策略种子数据，为内置角色配置 `requirement_import` 权限。

## 3. 导入字段（12个可编辑字段 + 1个可选字段）

| 序号 | 字段名 | 数据库字段 | 必填 | 校验规则 | 默认值 |
|------|--------|-----------|------|----------|--------|
| 1 | 需求编号 | requirement_no | 否 | 若填写需符合格式 `RQYYYYMMDDnnn`（13位）；若为空则自动生成 | 自动生成 |
| 2 | 需求标题 | title | **是** | 非空文本 | 无 |
| 3 | 详细描述 | description | **是** | 非空文本 | 无 |
| 4 | 需求提出人 | proposer | **是** | 非空文本 | 无 |
| 5 | 当前责任人 | assignee | **是** | 非空文本 | 无 |
| 6 | 关联问题 | related_issues | 否 | 多个问题以逗号分隔，存为JSON数组 | 空 |
| 7 | 需求单号 | external_req_no | 否 | 文本 | 空 |
| 8 | 计划落地版本 | planned_version | 否 | 文本 | 空 |
| 9 | 计划落地日期 | planned_date | 否 | 日期格式 `YYYY-MM-DD`，需为有效日期 | 空 |
| 10 | 优先级 | priority | **是** | 整数 1-10 | 5 |
| 11 | 需求分类 | category | **是** | 固定选项：管控需求/内核需求/管控和内核需求/其他 | 其他 |
| 12 | 需求价值 | value | **是** | 固定选项：质量加固/性能提升/竞争力提升/定位能力提升/恢复能力提升/感知能力提升 | 质量加固 |
| 13 | 状态 | status | 否 | 固定选项：待分析/待RAT决策/开发中/已经落地；更新模式下需遵循流转约束；新增模式下默认为「待分析」 | 待分析 |
| 14 | 备注 | remark | 否 | 文本 | 空 |

> **注意**：优先级、分类、价值若填写为空或无效值，使用默认值而非报错（宽松处理）。状态字段若填写为空，新增模式默认「待分析」，更新模式保持原状态。

## 4. 模板文件设计

- **格式**: Excel (.xlsx)
- **Sheet名称**: `需求导入模板`
- **第一行**: 表头（14列，按上述字段顺序）
- **第二行**: 示例数据行（填写示例值，帮助用户理解格式）
- **表头样式**: 加粗、居中、边框（参考导出功能样式）
- **文件名**: `需求导入模板.xlsx`

---

## 5. 冲突检测规则（仅需求编号）

| 场景 | 处理方式 |
|------|----------|
| 需求编号为空或未填写 | **新增模式** — 系统自动分配新编号 `RQ{YYYYMMDD}{nnn}` |
| 需求编号填写但格式不合法 | **报错** — 行校验失败，提示「需求编号格式错误，应为RQ+8位日期+3位序号」 |
| 需求编号填写且格式合法，但不存在于数据库 | **新增模式** — 使用导入的编号（需校验编号是否已被当日其他需求占用） |
| 需求编号填写且匹配已有需求 | **更新模式** — 以导入数据更新该需求的其他字段 |

---

## 6. 更新模式下的状态流转约束

需求编号匹配时执行更新，需遵循现有系统的状态流转规则（仅允许正向流转或回退一步）：

| 已有需求状态 | 导入数据中的状态 | 处理方式 |
|-------------|-----------------|----------|
| 待分析 | 空 / 待分析 | 允许更新其他字段，状态不变 |
| 待分析 | 待RAT决策 | 允许更新（正向流转） |
| 待分析 | 开发中 / 已经落地 | **拒绝** — 报错「不允许从待分析跨步流转至{状态}」 |
| 待RAT决策 | 待分析 | 允许更新（回退一步） |
| 待RAT决策 | 开发中 | 允许更新（正向流转） |
| 待RAT决策 | 空 / 待RAT决策 | 允许更新其他字段，状态不变 |
| 开发中 | 待RAT决策 | 允许更新（回退一步） |
| 开发中 | 已经落地 | 允许更新（正向流转） |
| 开发中 | 空 / 开发中 | 允许更新其他字段，状态不变 |
| 已经落地 | 任何状态 | **拒绝** — 报错「已经落地的需求不可通过导入变更」 |

> **设计说明**：导入时不强制填写状态字段，若为空则保持原有状态。这样用户可只更新其他字段而不触碰状态。

## 7. 导入逻辑流程

```
1. 接收Excel文件
2. 按行读取数据（跳过表头行和示例行）
3. 全量校验所有行：
   - 必填字段检查（标题、描述、提出人、责任人）
   - 字段格式检查（日期格式、编号格式）
   - 状态流转约束检查（若编号匹配且填写了状态）
4. 若校验失败：返回错误报告，停止导入
5. 若校验成功：逐行执行新增或更新操作
   - 新增：INSERT + 写入操作日志（action=created）
   - 更新：UPDATE + 写入操作日志（action=updated或status_changed）
6. 返回导入结果（成功数量、新增数量、更新数量）
```

## 8. 后端接口设计

### 接口一：下载导入模板

```
GET /api/requirements/import-template
```

**查询参数**:
- `operator_id`: 操作人账号

**响应**:
- 成功：返回 Excel 文件流
  - Content-Type: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
  - Content-Disposition: `attachment; filename="需求导入模板.xlsx"`
- 失败：
  - 403: 无导入权限

---

### 接口二：导入需求

```
POST /api/requirements/import
```

**请求**: `multipart/form-data`
- `file`: Excel 文件（.xlsx）
- `operator_id`: 操作人账号

**成功响应** (200):
```json
{
  "success": true,
  "total": 50,
  "created": 30,
  "updated": 20,
  "message": "成功导入50条需求（新增30条，更新20条）"
}
```

**校验失败响应** (400):
```json
{
  "success": false,
  "error_type": "validation_failed",
  "errors": [
    {
      "row": 3,
      "field": "需求标题",
      "message": "必填字段不能为空"
    },
    {
      "row": 5,
      "field": "计划落地日期",
      "message": "日期格式错误，应为YYYY-MM-DD"
    },
    {
      "row": 8,
      "field": "状态",
      "message": "不允许从待分析跨步流转至已经落地"
    }
  ]
}
```

**其他失败响应**:
- 403: 无导入权限
- 503: 需求管理表未就绪

## 9. 实现要点

- 使用 `openpyxl` 解析 Excel（项目已有依赖）
- 校验阶段：逐行检查，收集所有错误，不执行数据库操作
- 执行阶段：使用事务，确保批量操作的原子性（全部成功或全部回滚）
- 新增需求的编号分配：调用现有 `_allocate_requirement_no` 函数
- 更新需求时：复用现有字段更新逻辑，遵循状态流转约束
- 操作日志：每条新增/更新都写入 `requirement_log` 表

## 10. 前端设计

### 按钮位置与交互

**按钮位置**:
- 在需求管理页面工具栏右侧，与「新建」「导出」按钮并列
- 新增两个按钮：
  - 「下载模板」按钮 — 点击直接下载模板文件
  - 「导入」按钮 — 点击打开导入弹窗

**白名单控制**:
- `requirement_import` 权限项控制两个按钮的显示

### 导入弹窗设计

点击「导入」按钮后显示弹窗：

**弹窗内容**:
- 标题：「批量导入需求」
- 说明文字：「请先下载模板，填写需求信息后上传」
- 文件上传区域：
  - 支持拖拽上传或点击选择文件
  - 仅接受 `.xlsx` 格式
  - 显示已选择文件名
- 操作按钮：
  - 「取消」— 关闭弹窗
  - 「确认导入」— 提交上传（按钮有loading状态）

### 交互流程

```
1. 用户点击「下载模板」
   → 调用 GET /api/requirements/import-template
   → 浏览器下载文件

2. 用户填写Excel模板

3. 用户点击「导入」按钮
   → 显示导入弹窗

4. 用户选择/拖拽Excel文件
   → 前端校验文件格式（仅.xlsx）
   → 显示文件名

5. 用户点击「确认导入」
   → 按钮显示loading状态
   → 调用 POST /api/requirements/import
   → 等待响应

6. 导入成功：
   → 关闭弹窗
   → 显示成功提示：「成功导入N条需求（新增X条，更新Y条）」
   → 自动刷新需求列表

7. 导入失败：
   → 弹窗内显示错误信息
   - 校验失败：列出各行错误（行号+字段+原因）
   - 权限失败：提示「无导入权限」
   - 其他错误：提示具体错误信息
   → 保持弹窗开启，用户可重新选择文件
```

### 状态管理

新增状态项：
- `state.reqImportLoading` — 控制导入按钮loading状态
- `state.reqImportModalVisible` — 控制导入弹窗显示/隐藏

## 11. 错误处理汇总

| 场景 | 后端响应 | 前端处理 |
|------|----------|----------|
| 无导入权限 | 403 | 弹窗提示「无导入权限」 |
| 需求管理表未就绪 | 503 | 弹窗提示「需求管理表未就绪」 |
| 文件格式错误（非xlsx） | 400 | 前端预校验阻止上传；后端返回400时提示「仅支持xlsx格式」 |
| 必填字段为空 | 400 validation_failed | 弹窗内列出错误行（行号+字段名+原因） |
| 日期格式无效 | 400 validation_failed | 弹窗内列出错误行 |
| 需求编号格式无效 | 400 validation_failed | 弹窗内列出错误行 |
| 状态流转不合法 | 400 validation_failed | 弹窗内列出错误行 |
| 已经落地需求被尝试更新 | 400 validation_failed | 弹窗内列出错误行 |
| Excel文件损坏/无法解析 | 400 | 弹窗提示「文件无法解析，请检查文件格式」 |
| 导入成功但无数据（空Excel） | 200 success | 提示「导入成功，共0条需求」 |
| 网络错误/超时 | — | 提示「导入失败：网络错误，请重试」 |

## 12. 测试要点

**权限测试**:
- 无权限用户看不到下载模板和导入按钮
- 无权限用户直接调用接口返回403

**模板下载测试**:
- 模板包含14个字段表头
- 模板包含示例数据行
- 文件格式为xlsx

**校验测试**:
- 必填字段为空时正确报错
- 日期格式无效时正确报错
- 需求编号格式非法时正确报错
- 状态跨步流转时正确报错
- 已经落地需求被更新时正确报错

**导入成功测试**:
- 全新增场景：需求编号为空，自动分配编号
- 全更新场景：需求编号匹配已有需求，更新字段
- 混合场景：部分新增、部分更新
- 操作日志正确记录（created/status_changed/updated）

**边界测试**:
- 空Excel（仅表头）：返回成功，导入0条
- 单行数据：正确处理
- 大批量数据（如100行）：性能可接受

**并发测试**:
- 同一需求编号被两行同时导入：后端事务保证一致性
