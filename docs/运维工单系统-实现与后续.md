## 1. 系统目标（业务）

- **运维工单平台**：工单在多个节点间流转；后端 Python（**FastAPI**）；数据库 **GaussDB**；存储工单字段与附件（Word/TXT 等）。
- **权限**：先不做，最后再做。
- **处理人规则**：每个节点**仅一名**处理人；可由**发起人选择**，或由规则**自动带出**（如 HCS 提单按时间与问题类型从**值班表**选人；自建提单由发起人选下一步处理人）。
- **流转动作**：提交下一节点、跳转提交下一节点、回退上一节点、挂起、最后节点关闭；**回退只能到上一节点**；回退后上一节点可再次处理并再次前进。
- **数据保留**：各节点填写内容**保留记录**，允许覆盖；附件作为**节点字段**呈现，不单开附件页。
- **操作日志**：每次流转落库（操作者、时间、动作等）。
- **通知**：曾约定接口预留；后又说站内消息先不做——以**最新口径**为准，需要时再补。
- **浏览器**：仅 **Chromium**（Chrome/Edge）。

## 4. 后端与数据（待实现 — 下一对话主要工作）

### 4.1 技术选型（已定）

- **API**：FastAPI  
- **DB**：GaussDB（表结构、索引、事务、附件元数据或大对象策略需设计）

### 4.2 建议优先落地的模块（按依赖顺序）

1. **流程 ID**：格式 `YW` + `YYYYMMDD` + **三位循环** `000–999`（如 `YW20260402078`）。
2. **工单主表 + 节点实例表 + 流转记录表**（操作日志）。
3. **两种提单模板**：HCS（7 节点）vs 自建（5 节点）；节点可跳转；回退仅上一节点。
4. **处理人解析**：自建选人；HCS 按时间与问题类型查值班表。
5. **附件**：上传/下载/删除；与节点字段绑定。
6. **权限表**：后做；与提单入口、处理人白名单联动（用户曾描述「权限 CRUD 触发白名单」）。

### 4.3 前端后续对接
