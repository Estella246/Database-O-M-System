# 各值班表与生效时间

## 通用口径

- 后端时区统一使用 `Asia/Shanghai`。
- “工作日/周末节假日”只有两个选项；以系统“节假日配置”为最高优先级，未配置时按自然周末判定。
- 时间窗口边界按以下规则：
  - 工作日白班：`[09:00, 18:00]`
  - 工作日晚班：`(18:00, 次日09:00)`
  - 周末节假日全天：`[09:00, 次日09:00)`
- 人员状态只有“当值/非当值”。
- 命中值班表/轮值表时，统一按同一算法分配：在“当值”人中选择“最近接单时间”最早者。
- 轮值表派单命中时，同步更新该人员在**全部轮值表**中的「最近接单时间」；不更新任何值班表（`duty_calendar_assignment`）。
- 值班表派单命中时，仅更新对应值班表行上的接单时间与派单审计字段；**不更新**任何轮值表。
- “最近接单时间”更新时间：在系统计算出下一步处理人时立即更新。
- **轮值表维护（PUT `/api/duty/rotation`）**：仅维护各轮值表的人员列表、顺序、当值状态；**不修改**「最近接单时间」及派单审计字段（由工单派单写入；管理员保存轮值表时服务端保留库内已有值）。

## 内核值班表

- 可配置“全天”“晚班”。
- “晚班”生效：工作日 `18:00~次日09:00`。
- “全天”生效：周末节假日 `09:00~次日09:00`。

# 一、问题填写阶段流转规则

在“问题填写”阶段点击提交后，自动流转到“问题审核”阶段；不手工指定下一步处理人，由后端自动分单。分单结果写入「问题审核」节点的下一步处理人。

## 派单优先级（问题填写 → 问题审核）

按以下顺序**依次判定**，命中即停止，不再看后续条件：

1. **问题阶段** = `在研版本试点` → 在研版本轮值表 / 在研版本值班表
2. **问题阶段** = `POC阶段` → POC 轮值表 / POC 值班表
3. **产品线** = `公有云` → 公有云轮值表 / 公有云值班表
4. **问题组件**（内核问题 / 管控问题）→ 内核/管控轮值表与值班表

## 在研版本试点问题（最高优先级）

- **判定**：问题填写节点「问题阶段」=`在研版本试点`（`biz_env`）；与产品线、问题组件同时填写时仍优先走本规则。
- **分单规则**（问题审核处理人）：

| 窗口 | 时段 | 派单数据源 |
|------|------|------------|
| 工作日白班 | `[09:00, 18:00]` | 在研版本轮值表 |
| 工作日晚班 | `(18:00, 次日09:00)` | 在研版本值班表（晚班） |
| 周末节假日 | `[09:00, 次日09:00)` | 在研版本值班表（全天） |

## POC 阶段问题（次于在研版本试点）

- **判定**：问题填写节点「问题阶段」=`POC阶段`（`biz_env`）；未命中在研版本试点时生效。
- **分单规则**（问题审核处理人）：

| 窗口 | 时段 | 派单数据源 |
|------|------|------------|
| 工作日白班 | `[09:00, 18:00]` | POC 轮值表 |
| 工作日晚班 | `(18:00, 次日09:00)` | POC 值班表（晚班） |
| 周末节假日 | `[09:00, 次日09:00)` | POC 值班表（全天） |

## 公有云问题（次于 POC 阶段）

- **判定**：问题填写节点「产品线」=`公有云`；未命中上述问题阶段时生效。
- **分单规则**（问题审核处理人）：

| 窗口 | 时段 | 派单数据源 |
|------|------|------------|
| 工作日白班 | `[09:00, 18:00]` | 公有云轮值表 |
| 工作日晚班 | `(18:00, 次日09:00)` | 公有云值班表（晚班） |
| 周末节假日 | `[09:00, 次日09:00)` | 公有云值班表（全天） |

## 其他问题（混合云等，按问题组件）

### 组件限制

- “问题组件”只允许：`内核问题`、`管控问题`。

### 分单规则

1. 工作日白班 `09:00~18:00`：  
   根据“问题组件”选择轮值表：
   - 内核问题：内核轮值表
   - 管控问题：管控轮值表
2. 工作日晚班 `18:00~次日09:00`：  
   根据“问题组件”选择值班表（晚班）：
   - 内核问题：内核值班表
   - 管控问题：管控值班表
3. 周末节假日 `09:00~次日09:00`：  
   根据“问题组件”选择值班表（全天）：
   - 内核问题：内核值班表
   - 管控问题：管控值班表

# 二、问题审核阶段流转规则

在“问题审核”阶段提交后，下一步处理人按以下规则确定。

## 1）处理方式 = 确认问题

- 自动流转到“运维分析”阶段。
- 处理人“本人”定义为：**该节点当前处理人**（非当前操作提交人）。

## 2）处理方式 = 提交其他运维审核

- 仍留在“问题审核”阶段（同节点转办）。
- 展示「下一步处理人」，由操作人**手动选择**；未选择时回退为**本人**（当前提交人）。
- 不展示「专项轮值表」，不自动命中轮值表。
- **轮值表接单时间（公平性）**：若工单**首次进入问题审核**时处于工作日白班 `09:00~18:00`（`workday_day`），且成功转办给**他人**（当前处理人 ≠ 下一步处理人），则：
  - **当前处理人**在**全部轮值表**中的「最近接单时间」重置为 `2000-01-01 00:00:00`（便于下次白班派单优先轮到转出者）；
  - **下一步处理人**在**全部轮值表**中的「最近接单时间」更新为提交时刻。
- 不涉及值班表（`duty_calendar_assignment`）。

## 3）处理方式 = 提交专项轮值表

- 仍留在“问题审核”阶段（同节点转办）。
- 展示「专项轮值表」（仅专项类选项），按选项命中对应**专项轮值表**：
  - 慢SQL(SQL调优) -> 慢SQL专项轮值表
  - 整体性能 -> 整体性能专项轮值表
  - 升级 -> 升级专项轮值表
  - 扩容 -> 扩容专项轮值表
  - 备份恢复 -> 备份恢复专项轮值表
  - 容灾 -> 容灾专项轮值表
  - 管控问题 -> 管控轮值表
- **仅工作日白班** `09:00~18:00`（`workday_day`）执行上表派单；工作日晚班、周末节假日及轮值表无当值人员时，下一步处理人为**本人**（当前提交人）。
- **轮值表接单时间（公平性）**：与「提交其他运维审核」相同——工单首次进入问题审核时为 `workday_day`，且成功转给他人时，同步重置转出者与更新接手者在**全部轮值表**中的「最近接单时间」（专项派单命中时已更新接手者，仍按同一口径落库）。

# 三、统一兜底与审计

- 当依次遍历规则后无可用处理人，下一步处理人默认回退“本人”（该节点场景定义下的本人）。
- 命中值班表后需落库命中规则明细，记录在各值班表的审计字段中（如：命中时间、命中工单、命中节点、命中规则）。
# 四、开发闭环阶段流转规则

在「开发闭环」阶段，处理方式为 **提交运维闭环** 或 **返回运维分析** 时：

- 「提交运维闭环」→ 流转到「运维闭环」；「返回运维分析」→ 流转到「运维分析」。
- 「下一步处理人」**默认**为**运维分析阶段最后一次提交人**（`ticket_flow_log` 中 `from_node=ops_analysis` 且 `action_type` 为 `submit`/`jump_submit` 的最近一条操作人）；前端选中上述处理方式时展示该默认人。
- 操作人可手改下一步处理人；若提交时未填写，后端按上述默认补全。
