# 质量改进模块 使用手册

> 面向使用者的操作说明：能看到什么、怎么操作、规则是什么。

---

## 这是什么

运维工作中发现的问题、想到的改进，总需要有人跟进、有人审批、有人落实。质量改进模块就是干这个的。

每条改进建议会走一条固定的审批路径：**提出 → 评审 → 确认 → 实施 → 验收**。最终形成可追溯的改进记录。

入口在侧栏「质量管理 → 质量改进」，也可以在工单流程里直接创建。

---

## 谁能做什么

权限由管理员在「权限策略」里按角色授予：

- **质量改进**：能不能看到这个模块、进到列表页。
- **质量改进 / 新建按钮**：能不能新建、编辑、提交、删除。
- **质量改进配置**：能不能配置白名单、迁移旧数据。
- **质量改进统计**：能不能看统计看板。

没授「质量改进」的角色完全看不到这个模块。

---

## 新建一条改进建议

进入「质量改进」→ 点「新建」，填表：

| 字段 | 填什么 | 必填？ |
|---|---|---|
| 改进标题 | 用一句话说清要改进什么 | 必填 |
| 分类 | 定位定界 / 易用性提升 / 特性加固 / 快速恢复 / 产品规格 / 升级 / 资料 | 必填 |
| 优先级 | 高 / 中 / 低 | 选填，默认中 |
| 领域 | 从责任田树选，比如 SQL引擎 | 选填 |
| 模块&特性 | 级联下拉，选了领域后才能选模块，比如 驱动/JDBC | 选填 |
| 关联运维系统单号 | 必须是系统里存在的 YW 单号 | 必填 |
| 详细描述 | 富文本，可以加粗、插图 | 必填 |
| 下一步处理人 | 选谁来评审，从评审人白名单里挑 | 必填 |

填完有两个按钮：

- **提交评审**：分配编号，直接进入评审阶段。
- **保存**：存为草稿，不进评审，编号也不分配。什么时候提交了什么时候给编号。

比如：你在处理工单 YW20260716001 时发现一个需要改进的地方，新建改进建议，关联上这个工单号，填好标题和描述，选张三做评审人，点「提交评审」——这条建议就到了张三的待办里。

---

## 五个阶段怎么走

每条改进建议当前停在某个阶段，**只有当前阶段的处理人能操作**。

### 提出

处理人：**提出人自己**。

填好上面那张表，点「提交评审」，单子就流转到评审阶段了。

如果是草稿，可以反复修改，想好了再提交。

### 评审

处理人：**你填的评审人**。

评审人看到单子后做判断：

- **通过**：指定下一步的责任人（从分析人白名单选），写评审意见，单子进入确认阶段。
- **不通过关单**：写清不通过的理由，单子直接关闭，不能再改。

比如张三收到你提的建议，看完觉得靠谱，选了李四做责任人，点「通过」——单子就到了李四手上。

### 确认

处理人：**评审阶段指定的责任人**。

责任人决定是否接纳这条改进：

- **接纳**：指定实施责任人、选闭环方法（问题单闭环或需求闭环）、写评审意见，单子进入实施阶段。
- **不接纳**：写明理由，单子打回评审阶段重新处理。

### 实施

处理人：**确认阶段指定的责任人**。

填闭环信息：

- 问题单号或需求单号（看选了哪种闭环方法，标签会自动切换）。
- 当前进展（按闭环方法动态出选项）。
- 闭环效果自测、解决版本、SLA 时间。

填完点「提交验收」，单子进入验收阶段。

如果 SLA 时间过了还没提交验收，列表里会标红显示「超期」。

### 验收

处理人：**提出人**。

- **通过**：写验收结论，单子关闭，流程结束。
- **不通过**：写验收结论，单子打回实施阶段重新做。

### 整体流程图

```
你 ──提交评审──→ 评审人
                    │
          ┌────────┴────────┐
        通过               不通过关单
          │                    │
          ▼                  关闭
       责任人
          │
    ┌─────┴──────┐
  接纳         不接纳(打回评审)
    │
    ▼
  实施责任人 ──提交验收──→ 你
                             │
                   ┌─────────┴────────┐
                 通过              不通过(打回实施)
                   │
                   ▼
                 关闭
```

## 改已走过的阶段

阶段提交后，前面的阶段默认变成只读。但提交过那个阶段的人可以在一定范围内修改：

- 只能改**紧挨着当前阶段**的前一阶段。再往前的锁定了。
- 后面阶段已经用过的字段不能再动。比如评审人已经被评审阶段用过了，提出阶段就不能改评审人。

举个例子：单子到了确认阶段，你作为提出阶段的提交人，可以回去改标题、改描述。但不能改评审人，因为评审阶段已经用了。

## 把单子转给别人

处理人的名字旁边有一个「转单」按钮。你请假、出差、或者这条改进不该你管了，可以转给其他人。

点击「转单」，弹出一个搜索框，输工号或姓名搜索候选人，选中后点确认。单子的当前阶段不变，处理人变成你转给的那个人。

- 评审阶段的候选人来自**评审人白名单**。
- 确认和实施阶段的候选人来自**分析人白名单**。
- 提出和验收阶段没有白名单限制，所有活跃用户都能转。
- 验收阶段也能转，不再锁死为提出人。

转单后会在流转日志里留下记录，谁转的、转给谁、什么时候转的，都能查到。

---

## 在工单里创建改进建议

处理工单时（开发分析 / 开发闭环 / 运维闭环三个阶段），页面底部有「改进建议」区域，可以直接新建：

1. 点「+」号，填改进建议（字段和前面一样，**含下一步处理人**）。
2. 点「暂存」——建议存为草稿，挂在工单上，不进评审。
3. 等工单走到运维闭环提交时，这些草稿会**自动批量提交到评审**，统一分配编号。

这样做的好处是：处理工单时顺手记录改进点，不用切到质量改进模块单独建。

**注意**：工单弹窗里「下一步处理人」是必填的，不然提交不了。所以弹窗没有"提交评审"按钮，只有"暂存"——暂存后等闭环时统一提交。

### 草稿去哪看

工单里暂存的草稿，在「质量改进」列表切换到"**我提出的**"标签就能看到。草稿不会出现在"全部"和"我处理的"里。等闭环批量提交评审后，就会正常出现在评审人的待处理列表里。

## 管理员配置

侧栏「质量管理 → 质量改进配置」（需要「质量改进配置」权限）。

### 白名单

评审人、分析人分别维护一份名单。提出阶段选「下一步处理人」、确认阶段选「责任人」时，只能从对应白名单里选。

编辑模式下可以搜索、全选。勾好保存即可。

比如要加一个新评审人：进配置页 → 切到「评审人」tab → 点编辑 → 搜索人名 → 勾上 → 保存。

### 闭环进展

为「问题单闭环」和「需求闭环」分别配置进展阶段项。实施阶段的「当前进展」下拉就从这里取选项。

### 迁移旧数据

把旧「需求管理」的数据一次性导入新版。只迁核心字段（标题、描述、分类、优先级、提出人），导入后停在提出阶段，由各提出人后续手动提交评审。重复点不会重复导入。

---

## 统计分析

「质量改进统计」菜单（需单独授权，和统计图表是分开的权限）。

看板展示总数、进行中、超期的 KPI，以及阶段分布、分类分布、耗时排行。默认看全量数据，也可以选近 1 周 / 近 1 月 / 近 3 月，或自定义日期范围。

## 常见问题

**提交时报"仅当前处理人可提交"？**

每个阶段只有当前处理人能操作。提出阶段是提出人，评审阶段是评审人，确认和实施阶段是责任人，验收阶段是提出人。换个人登录就提交不了。

**草稿为什么没编号？**

草稿不分配编号。提交到评审时才统一分配 ZLGJ-YYYYMMDD-NNN。这样废弃的草稿不会占编号。

**列表里"超期"怎么来的？**

实施阶段填了 SLA 时间。如果当前阶段不是关闭状态，且已经过了 SLA 时间，就标红超期。

**能删掉一条改进建议吗？**

只在提出阶段、且是创建人本人（或管理员）才能删。进了后续阶段的删不了。

**评审不通过会怎样？**

评审不通过，单子直接关闭，流程结束。

**分析不接纳、验收不通过会怎样？**

分析不接纳，打回评审重新来。验收不通过，打回实施重新做。都不是关闭，给了改的机会。

**选不到我要的处理人？**

找管理员，把那个人加到对应的白名单里（评审人白名单或分析人白名单）。

**工单弹窗里建的草稿去哪了？**

在「质量改进」列表切换到"我提出的"标签就能看到。草稿不会出现在"全部"和"我处理的"这两个标签里。

**验收阶段还能转单吗？**

能。之前确实锁死为提出人，现在可以转了。转过去后对方能以验收人身份操作。

**工单弹窗建草稿时报"下一步处理人不能为空"？**

弹窗里"下一步处理人"是必填的。输入工号或姓名搜索，从下拉候选里选一个评审人。选不了的话找管理员把你加到评审人白名单。
