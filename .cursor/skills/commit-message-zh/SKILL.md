# 提交信息用中文

## 硬性要求

在本仓库创建 **git commit** 或 **PR 标题/摘要** 时：

1. **提交说明必须使用中文**（标题与正文均用中文，勿用英文句子充当主文案）。
2. 类型前缀可保留英文惯例：`feat` / `fix` / `docs` / `test` / `refactor` / `chore` 等。
3. 冒号后的描述、正文段落、变更原因 — **全部中文**。

## 推荐格式

```
<type>(<scope>): <中文一句话摘要>

<可选：1–3 句中文说明「为什么改」，勿堆文件列表>
```

### 示例

```
feat(leave): 新建申请支持关键字搜索选择申请人

默认填入当前登录人，交互与审批白名单添加人员一致；后端支持代他人申请。
```

```
fix(duty): 修复值班表导入时文件选择与解析失败

统一走与用户管理相同的人员池校验，避免选文件后无响应。
```

```
docs: 更新 README 中请假申请说明
```

## 撰写要点

- **摘要**：说清用户可感知的变化，不要只列文件名。
- **正文**：解释动机与影响；无必要可省略正文，但标题仍须中文。
- **scope**：用模块短名即可，如 `leave`、`duty`、`stats`、`admin`。
- **避免**：`update code`、`fix bug`、`WIP`、纯英文描述。

## 执行提交时

1. 先 `git status` / `git diff` 理解变更范围。
2. 按上文格式起草**中文**提交信息。
3. 用 HEREDOC 传 `-m`，避免 shell 转义问题。
4. 勿提交 `.env`、密钥、无关自动生成物（如 coverage 报告），除非用户明确要求。

## 与 PR 的关系

创建 Pull Request 时：

- **Title**：与 commit 标题同风格，中文摘要。
- **Summary / Test plan**：中文条目说明变更与验证步骤。
